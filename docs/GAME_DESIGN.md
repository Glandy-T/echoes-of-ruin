# ゲームデザイン

## 世界観概要

タイトルおよびゲーム内の文言から、終末後と思われる環境に端末認証とロックされた通路が存在することは確認できる。端末では「生体反応を確認。認証完了。」と表示され、認証によって先へのドアが解放される。

作品テーマと作者用の完全な世界設定は [WORLD_BIBLE.md](WORLD_BIBLE.md) に、プレイヤーへ開示する情報は [STORY_REVEAL_PLAN.md](STORY_REVEAL_PLAN.md) に分離して記録する。主人公の名前、年齢、記憶喪失以前の経歴、登場人物、敵対存在、探索の最終目的、「残響」の具体的な意味は **TBD**。

### 生存要素の扱い

- 本作はサバイバルゲームではなく、食料・水分・睡眠を数値管理するシステムは採用しない。
- 食料や水は環境調査対象として存在してよいが、主人公が定期的に摂取する操作や演出を必須にしない。
- 時間経過や休息が必要な場合は、章間・場面転換などの短い過場演出で処理し、探索テンポを妨げない。
- 主人公の長期的な生存可能性は本編の主題とせず、真相解明後の未来も描写しない。

## 序章の工業区表現

序章の工業区は、生産・物流・備蓄・保守・保安が高度に自動化され、一体化していた都市外縁の重要インフラ区域として扱う。旧来の大量の工場労働者や常備軍人は存在せず、少数の生産・保安要員が、重要資源の生産承認、設備管理、ロボット群の監督、施設警備を兼務していた。現在の世界で利用可能な電力が残る唯一の区域だが、重要設備用の独立予備電源は枯渇寸前で、生命維持、緊急覚醒、非常照明、認証、最低限の自動扉などだけが動作している。主人公の覚醒は通常予定ではなく、長期生命維持を継続できなくなったシステムによる最後の緊急処理である。現在活動できるロボットは存在しないが、施設には人間とロボットの共同運用を前提とした構造が残る。工業区内部は、略奪や内部暴動で崩壊した場所ではなく、長期の無保守、老朽化、エネルギー枯渇、局所的な構造損傷を受けながらも、整然とした制度的秩序を残す場所とする。社会混乱期にも生産中枢は一般市民へ開放せず、物資支援は外縁の管理地点から限定的に行った。

この秩序感は、後に訪れる下層居住区の過密、混乱、仮設構造、抗争の痕跡と対比させる。序章で提示できる情報と禁止する真相は [STORY_REVEAL_PLAN.md](STORY_REVEAL_PLAN.md) に従い、工業区上層管理者の最終的な撤離や地球外移民との関係を工業区で確定させない。

## 主人公設定

詳細な人物設定と台詞規則は [CHARACTER_DESIGN.md](CHARACTER_DESIGN.md) を正とする。

### 性格と行動原理

主人公は記憶を失っている。しかし、状況に怯えて消極的になる人物ではない。不安を抱えながらも、まず周囲を観察し、自ら行動して答えを探そうとする積極性を持つ。

- 冷静で観察力があり、未知の場所や異常な状況でも、得られる情報を確かめながら進む。
- 表面上は淡々としているが、他者や失われた生活の痕跡に対する思いやりを失ってはいない。
- 廃墟、死者、失われた生活の痕跡から強い影響を受ける場面では、無理に冗談を言わない。沈黙または短い言葉で、不安や共感を示す。

### 台詞の方向性

主人公は時折、皮肉やブラックユーモアを交えた発言をする。ただし、話し好きではなく、すべての事柄に反応する人物でもない。皮肉はプレイヤーを笑わせるためではなく、理解できない状況や恐怖に対して冷静さを保つための態度として扱う。

台詞は、作者自身の自然な感想を出発点にしてよい。ただし、主人公がその時点で知っている情報、性格、置かれた状況を通して調整する。以下を方針とする。

- メタ的な発言、過度な説明、頻繁な冗談は避ける。
- 感情の強い場面では、説明的な長台詞より沈黙や短い言葉を優先する。
- 終末世界の静かな雰囲気を損なわないことを重視する。

## インタラクションシステム

詳細な仕様と実装ステータスは [INTERACTION_SYSTEM.md](INTERACTION_SYSTEM.md) を正とする。

### 目的

探索中の調査体験を統一しつつ、情報量の異なる対象に応じて見せ方を変える。環境観察と情報読解の両方を自然に行えるようにし、主人公視点による物語理解を強めることを目的とする。

### 調査可能な物体の表示

探索中に調査可能な物体へ近づくと、その物体の名前を画面上に短く表示する。表示位置は対象物の上方とし、プレイヤーが「ここは調べられる」と直感的に理解できるようにする。プレイヤーが対象から離れた場合、名前の表示は消える。

### 調査結果の表示形式

調査ボタンを押したときの表示は、対象の情報量に応じて次の 2 種類に分ける。

| 種別 | 対象 | 表示方法 |
| --- | --- | --- |
| 詳細表示型 | 持ち運び可能な道具、掲示物、書類、記録媒体、重要アイテム | 詳細画像を画面に表示した後、主人公の会話ボックスで対象への感想や考察を示す。 |
| 簡易表示型 | 休眠ポッド、機械設備、ドア、壁、家具、背景に近い環境物 | 詳細画像は表示せず、主人公の会話ボックスのみで反応を示す。 |

### 台詞方針

調査時の台詞は「主人公設定」に従う。冷静かつ積極的に状況を捉え、必要に応じて控えめな皮肉やブラックユーモアを用いる。ただし、主人公が話しすぎないこと、終末世界の静かな雰囲気を壊さないことを優先する。

### 実装状況

本仕様は今後の調査体験に関するゲームデザインである。現行実装では、`Area2D` への接近時に共通の操作ヒントを表示し、調査時にテキストボックスを表示する機能まで実装されている。物体固有の名称を対象上方に表示する機能、および詳細画像を表示する詳細表示型は**未実装**である。

## ゲームのコアプレイ

現行実装のゲームループは以下のとおりである。

1. プレイヤーが左右移動とジャンプでマップを探索する。
2. `Area2D` の検知範囲に入ると、`E` キーによる調査・移動のヒントが表示される。
3. 端末を初回調査すると認証済み状態になり、対象ドアを開放する。
4. 開放後のドアを調べると次の部屋へ場面遷移する。
5. 次の部屋では戻り口を調べて開始マップへ戻れる。

### 操作

| 操作 | 現行実装 |
| --- | --- |
| 左右移動 | Godot 標準の `ui_left` / `ui_right`（README では矢印キー） |
| ジャンプ | `ui_accept`（README では Space / Enter） |
| 調査・決定 | `E`（入力アクション `interact`） |
| ポーズ | `Esc`（入力アクション `pause`） |

## 章構造

ゲームデザイン上の区域進行は、序章（外縁工業区／休眠施設）、第一章（下層居住区）、第二章（地下インフラ／下水道）、富裕層居住区、科学技術区、政治中枢区で構成する。都市は盆地状の低地を中心に拡張され、中央高地区へ向かうほど上層の生活・技術・政治機能へ近づく構造とする。各章での情報開示は [STORY_REVEAL_PLAN.md](STORY_REVEAL_PLAN.md) を参照する。現行プロトタイプに存在する進行単位は、次の 2 マップである。

| 段階 | シーン | 内容 |
| --- | --- | --- |
| 開始 | `res://scenes/core/title_screen.tscn` | タイトルと開始ボタン |
| Demo マップ 1 | `res://scenes/dev/prototype_room_a.tscn` | 端末認証、ドア解放、次の部屋への移動 |
| Demo マップ 2 | `res://scenes/dev/prototype_room_b.tscn` | Scene Exit からマップ 1 へ復帰 |

## マップ進行方向

現行の `prototype_room_a.tscn` は横長の 1 フロアである。`spawn_id = start` の開始地点は左側（x=298）、端末は右側（x=1591）、通行ドアはさらに右側（x=1700）に配置されている。そのため、現状の基本進行は**左から右**である。

`prototype_room_b.tscn` では左側の Scene Exit（x=105）から戻り、`prototype_room_a.tscn` の `spawn_id = from_room_b`（x=1702）に配置される。以後のマップ群、分岐、ショートカット、章ごとの進行方向は**要補足**。

設計上の序章では、主人公は工業区休眠施設の 4F 休眠区にある休眠処置室から下階へ進み、1 階を目指す。施設全体の構成、4F フロア監護ステーション、Room 1 の仕様は [MAP_DESIGN.md](MAP_DESIGN.md) を参照する。
