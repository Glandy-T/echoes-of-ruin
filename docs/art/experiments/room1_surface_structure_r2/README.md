## 这次具体做了什么

借鉴实际看到的分工：颜色图先有结构的亮边、暗面、材质色阶，几何负责原有空间。没有复制原作木结构、砖瓦、招牌、护岸水渍或配色，也没有将参考原作图像作为AI输入。

**墙：**暖灰矿物／陶瓷主面保留安静大面；现有灯槽重新绘制上唇亮边、内槽暗面与下收口，金属保护带重新安排面向与短亮色簇，墙脚沉积只沿实际下沿。灯罩仍是连续低饱和灰蓝白、22.5cm既有高度；不增加板缝、竖向端框、设备、文字、铆钉或螺丝。PixelLab结果擅自生成的上部盒状面板／灯槽竖向端框已剔除，结构由独立精确像素层校正。

**地：**沿用A版连续蓝灰，使用原生硬边材料簇，整理为少量低对比色阶；不加通道色带、砖缝、路线或损伤。独立审图指出初版孤立亮岛有污斑／迷彩感，已把不接边的大色岛归回底色（2,354像素），并把大面色差压低到-5..+6通道值。只有样段x=0对应的真实左墙侧有轻微接触收口，其余三个样段边缘不画框。局部大块形状与强度仍需审图，不能据“有像素簇”宣布已达到参考质量。

**接入：**仅左墙x=0.2、z=-6.4..-3.2m、高0..3.4m及相邻x=0.2..3.4、z=-6.4..-3.2m地坪使用新图，不再主面4%混入。审图发现初版窄过渡仍能读成竖向贴片端点，现新增独立原墙匹配层：每端8px精确回归原墙、随后40px分八阶交接，中央160px（2.0m）完整使用新结构。地面外沿过渡为0.192m。约80texels/m只是此次候选。没有把新纹理推广到全室。

房间尺寸、门／20舱／人物位置、模型轮廓、UV0／UV2、碰撞、玩法、原游戏Camera与r4灯光参数不改。工程及模型可编辑基准仍为[r4打包Blender](../room1_wall_finish_r4/room1_wall_finish_r4_packed.blend)，本轮新增可编辑内容是两份Aseprite、Godot材料源与原创guide／整理脚本。

## 来源与消耗

两次官方 PixelLab `/edit-images-v2`，只输入本项目原创guide：墙256×272、地256×256。实际完成记录为墙 **15**、地 **10**，共 **25次生成额度**；没有自动重投或额外生成。任务ID、固定seed入口、prompt、raw PNG及安全状态记录均在 `source/`、`guides/`、`raw/`。源脚本通过既有官方连接在内存中读取凭据；凭据不进入本目录、日志或GitHub。

墙面材质层整理为围绕#D3D6C9的五档色差；独立结构层保持既有世界高度。地面围绕#5A6C73整理为七档。清理仅移除极小断开像素岛，没有把全部表面再次模糊；结构和接触位置是项目手工指定，不能说成AI完全遵循约束或参考作者的制作步骤。

## 验证与限制

`source/verify_sources.py`直接读回Aseprite图层与可见cel：墙6层／地4层，原始AI和guide两层隐藏；可见合成与交付PNG逐像素一致。详见 `source/verification.json`。源文件检查不替代实际审图。

本次继承r4配套GLB、UV2、HDR和网格映射，Shader保留连续灯带的归一化与人物阴影。默认仅两份目标材质更换Shader，舱体特殊内光材质保持原状。新增N模式只为颜色图诊断：进入时快照非目标材质的原Shader／全部参数，所有烘焙接收材质一起显示固有色，退出完整恢复，避免只照亮新墙造成误判。技术近景的相机只存在于捕获脚本，不写入游戏场景。

当前实际应急照明仍明显压低墙地细节；颜色图可读不代表最终画面已达到Pixel Canals质量。本候选把这一限制与纯颜色对照一起交付，尚不正式推广整室或改定照明。

最终实际捕获为11张对比／模式还原图及13机位全室巡检，全部1280×720、未后期调曝光。原材质基线和N诊断往返后的基线，均与上一轮原版逐像素一致（变化像素0、最大通道差0）。父代理与独立审图复查了去除地面亮岛、墙面端点过渡及角部／门洞；未再见初版硬贴片端边或新的断灯。详见 `quality_record.json`。这些结论是候选与回归检查，不是整体美术达标或用户认可。

**新的固有色反射没有重烘焙。** 这份局部材料对照沿用r4照明，不是新的完整烘焙资产包。正式推广前仍需用户认可表面设计，再整理独立映射／整室配套解算；不能用局部修饰绕过已有UV、灯槽连续性与全室巡检规则。艺术精细度及照明下的阅读强度等待用户审查。

## 复现顺序

1. Python/Pillow运行 `source/prepare_guides.py` 重建原创guide；要复现此次结果应保留现有raw，而非重新调用AI。
2. `source/pixellab_job.py`按记录submit一次、之后只poll；记录存在便拒绝重复提交。重生会消耗额度且不保证相同。
3. 运行 `source/finish_maps.py` 生成原生PNG／独立图层；Aseprite批处理运行 `source/package_masters.lua` 保存分层源。
4. `source/verify_sources.py`核对源与PNG；Godot先导入PNG，再正常图形渲染运行 `capture_compare.gd` 和 `capture_room_survey.gd`。Headless只适合导入／编译，不用于实际截图。
5. 运行 `source/package_review.py` 生成预览。截图不调曝光、锐化或后期增强。
