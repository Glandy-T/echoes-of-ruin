- 仅 P12 的舱盖、长侧面、短端面三张外壳图。舱内、玻璃、屏幕、编号和灯管保持。其他 19 舱保持。
- A：r19 原版。
- B：仅换 PixelLab 较粗网格的新材料图，保留原光照表现。

## PixelLab 工作流

实际使用官方 API `POST /v2/inpaint-v3` 与后台任务轮询，读取现有已配置凭据，凭据不进入文件。仅提交本项目原创的干净结构导图与遮罩，**未上传 Pixel Canals 图片或任何第三方素材**。

四份新图分别在一半宽高的原生网格生成，再用 2× 最近邻整数放大回原图大小，UV 不变。生成前遮罩采用 2×2 最小值保护结构；生成后再用原尺寸精确遮罩恢复边线、编号、窗口、蓝灰支撑区和灯带。脚本不绘制污斑、不做人工调色或程序化材质。

这是**材料层**的 2× 网格试验，原有结构线／功能编号仍按原尺寸保护，不宣称全画面已经统一像素网格。

PixelLab 提示强调可读的连接像素簇、有限平面色阶与实际接触边缘的中等旧化，减少独立散点和柔和喷绘。输入不含旧细碎做旧；允许编辑区由新结果替换，不把新旧污迹叠加。

- `source/requests.json`：接口、种子、输入尺寸及任务清单。
- `source/prompt_*.txt`、`guide_*.png`、`mask_*.png`：实际原创输入和提示。
- `raw/`：PixelLab 未修改原始输出。
- `result_*.json`：真实后台任务 ID、完成状态与返回额度记录。
- `source/composite_validation.json`：遮罩／结构保护、范围外不变、输入／输出哈希。
- `editable/*.aseprite`：当前底层与 PixelLab 新层，可独立编辑／导出。

实际 6 个 API 请求，每次 10 generations，合计 **60 generations**；最终使用 4 张图。墙图第一次因灯带保护过宽导致保留旧细碎材料被弃用，第二次因 PixelLab 添加额外内框和枕头式面阴影被弃用。两次输入／原始输出／任务 ID／费用和拒用原因都保留在 `source/attempt1_wall/`、`source/attempt2_wall/` 与 `raw/wall_attempt*.png`，未手工修补这些纹理作为成品。

C 的初版硬舍入产生了明显的弯曲等高线。该组照明反例与对应 shader 保留在 `source/hard_step_attempt/`，最终比较使用柔和过渡；这次修正没有改任何 PixelLab 颜色图，也没有额外生成费用。

## 验收边界

本机最终验证：

- 14 份既有模型／布局／材质／正式入口文件的 SHA 保持；运行时 22,950 项不变性检查通过，含其他 19 舱与 Mesh／Collision 节点。
- 27 张 GPU 实际截图，均 1280×720；60 项相机／FOV／开闭／恢复检查通过。切回 A 的 P12 闭盖图与最初 A 逐像素相等。
- 4 份 Aseprite 母版回读与最终 PNG 逐像素相等，墙图样段外不变；实际任务与用量见 `source/artifact_validation.json`。
- 最终导入、运行验证和截图日志的 `ERROR:`／`SCRIPT ERROR:` 计数为 0。临时日志不上传；结构化结果与截图哈希保留。

实际观察：B 的舱体边缘和旧化比 A 更成块，细碎散点减少；C 相比 B 的改变较温和。硬舍入反例说明“强行减少光照色阶”会造成额外大斑块，不能把这种伪影当成像素风。该局部候选尚未由用户批准，不能据此宣布已复现参考或开始替换全室。

当前烘焙仍是 r19 的受光基线；本轮不重新计算新颜色可能引起的间接反弹变化，因此这是隔离变量的风格试验，不是最终光照交付。C 的局部明暗方案也只是候选；必须查看有无色阶条带、暗部吞细节及样段边界。

模型及正式项目的文件哈希、运行时节点／碰撞／其他 19 舱，以及 A 恢复均需核对。几何和 UV 未改，不另外生成新 GLB。技术相机不保存进游戏相机。用户审查前不把 r20 参数写入全项目规范。
