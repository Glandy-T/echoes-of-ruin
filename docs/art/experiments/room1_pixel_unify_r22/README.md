# Room 1 整室像素材质统一 r22

2026-10-30。用户比较 r20/r21 后认为 r20 更顺眼，确认不继续扩大颗粒，改做整室的视觉协调。本轮是独立待审版本，正式 F5 继续使用 r19；不改变模型、UV、布局、碰撞、人物比例或游戏相机。

## 方向与范围

以 r20 的材料尺度为基准，让已有墙缝、舱体肩部、密封边、灯槽和保护带的像素组织保持协调；保留安静的大面，不靠更多随机污渍模拟街区的信息密度。Pixel Canals 仍是风格/制作技法硬参考，不复制其具体场景，也不提交其 NoAI 内容给生成服务。

- 四墙使用 r20 一组既有双墙板，加五组全新 PixelLab 双墙板和一组门洞周边材质。清理旧墙体材料层再铺设，不把新旧污迹叠加。灯带维持 r13 的既有 PixelLab 灯罩/槽边图层与位置、能量。
- 20 个舱的外壳统一使用 r20 A 与新增 B/C/D 三套 PixelLab 差分。盖板/端面保留既有 01–20 功能编号；内腔、玻璃、动态屏幕和灯管不变。
- 连续蓝灰地坪采用八幅重叠、按真实房间坐标生成的 PixelLab 材料编辑；保留实际舱底足迹以及既定漏液位置，不加砖缝、通道色带、黄色沉积或新设备。
- 主门及其状态灯保持已审版，避免为了变化重做已经认可的部分。

## 制作来源

实际使用 PixelLab 官方 `POST /v2/inpaint-v3` 与后台任务查询。只提交项目自有导图、遮罩及已确认 PixelLab 地坪。保留 `source/requests.json`、实际提示/导图/遮罩、`raw/` 原始输出、真实任务 ID 与用量。

新材料在原图一半宽高的原生网格生成，再 2× 最近邻导出；不是把旧成品缩小后冒充新作品。结构/灯面/编号按照精确遮罩保护；地面重叠区域在原生像素网格选择误差较小的切线，只取真实 AI 像素，不画新纹理、不模糊拼缝。Aseprite 保留结构基底与 PixelLab 图层；脚本只做导图、遮罩、配准、编号转移和技术验证。

首张门洞周边输出虚构了内框，已拒用，另调用 PixelLab 墙面材料返修。B/D 两张舱盖误画了内层窗状面，D 还出现偏棕的面阴影，分别重新提交原始干净导图由 PixelLab 返修。第二块地坪出现白色接触光圈，使用原生精确遮罩另调用 PixelLab 修复，再组合两次真实 AI 输出，未手工着色；第八块出现大片白底，也通过原始项目导图重新生成。原图、返修输入与拒用原因保留在 `raw/` 与 `source/rejected_outputs.json`。

初始地坪 448×364 原生请求被服务端拒绝（要求更高订阅档位），该失败返回 USD 用量 0；第二幅初始大图未提交。随后改成八幅 256×256 原生请求，保持相同的世界像素尺度与原分辨率，未更改订阅。实际拼接位置见 `source/floor_tile_layout.json`，而不是已撤回的初始双图方案。

2× 指本轮材料层的技术缩放，不代表已经锁定全项目统一世界像素网格；功能编号、旧结构芯线与保留的灯罩仍保持既有像素。

可不消耗额度复现最终素材：使用已保存的 `raw/`，运行 `source/compose.py`，以 Aseprite 批处理运行 `source/package.lua`，再执行 `source/check_artifacts.py`。`jobs.py` 读取实际任务和完成记录，已完成任务不会重新付费提交；不应为了整理文件重新生成相同资产。

## 审查入口与交付边界

完成后运行 `scenes/dev/room1_pixel_unify_r22.tscn`（F6），1 原 r19 / 2 新整室，O 开闭 P12，H 说明。截图对照见本目录 `preview.html`。正式入口不变。

本轮沿用 r19 已验证的原几何/UV2与原始光照数据，未改变灯的位置、能量或增加硬明暗量化。新颜色引起的间接反弹尚未重烘，因此这里只审材料协调，不把旧光图称为新配套光照。通过整室材料审查后再决定是否计算最终配套烘焙。

`room1_pixel_unify_r22.blend` 是另存的材质源：只把 r19 的颜色图路径更新到新候选，保留原对象、几何、UV、相机和灯。它不是新烘焙，不含 Godot 动态屏幕/门灯实现；实际画面以 Godot 截图为准。通过重新打开文件核对对象状态与相对路径依赖。

检查应覆盖前后两排左中右、四角、真实显示的前墙、门洞/灯带接头、地面及20舱，并检查开闭、玻璃和编号。技术机位只存在于截图脚本，不保存为游戏镜头。实际结果、Aseprite 回读、基线哈希及 API 用量以 `source/` 的结构化验证为准。

初版对照工具把初始化时全部 Shader 参数一并恢复，误触当前开盖 GI 混合，导致 A→B→A 画面轻微变暗；单看贴图／光图路径检查没有发现。后续修正限制为本轮实际变更的参数，不覆盖当前开闭、人物阴影或光能。原失败与隔离诊断保留；以最终 `capture_validation.json` 为实际复位结果。此项是对照工具修正，不是新烘焙或 PixelLab 贴图调整；对应规则已补入 [光照 QA](../../ROOM1_LIGHTMAP_QA.md)。
