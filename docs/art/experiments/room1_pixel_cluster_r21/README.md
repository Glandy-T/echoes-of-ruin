2026-10-30。用户认为 r20 B／C 变化小、仍偏普通 3D，要求颗粒与块面更明确。**继续只做局部候选，不修改正式 F5 或推广整室。**

## 本轮区别

上一轮材料层为 2× 原生像素网格；本轮改为 **4× 网格**，让 PixelLab 在更低的有效分辨率中重新组织连接像素簇、明暗块面与既有边缘。不是把旧图缩小后直接冒充新画，也不降低烘焙采样制造噪声。

此前墙面提示要求“主面基本只有一个平色”，限制了块面信息。本轮允许有组织的浅／中／深材质层次，要求粗颗粒成组、阶梯边界清楚；仍不允许虚构凸起内框、枕头式明暗、新设备、孔洞或无来源的漂浮污块。

本次三组**保持完全相同的原光照和 shader**，不继续采用上轮帮助较小的柔和光照分级：

1. 原整室 r19。
2. 上轮 r20 B（2× 材料网格）。
3. 本轮 r21（4× 材料网格＋PixelLab 加强块面）。

它们比较的是实际贴图绘画差异。没有更改相机、曝光、分辨率、模型、UV、布局、碰撞、光图或灯参数。

## 固定样段

- 仅 P12 的舱盖、长侧面、短端面三张外壳。舱内／玻璃／屏幕／编号保持，其他 19 舱不变。
- 保护功能标识和原有结构时仍保留原尺寸像素；4× 是本次材料层试验，不是全项目像素密度规格。

## 原创输入与制作记录

实际使用 PixelLab 官方 `POST /v2/inpaint-v3` 及后台任务读取；凭据只在内存使用，不写入成果。所有输入都是本项目原创干净导图／遮罩，未上传 Pixel Canals 的截图、模型或贴图。Pixel Canals 仅供人工观察其低模与像素绘画分工；原作者的精确 UV、Shader、贴图尺寸仍未确认。

原生有效区域：墙 64×64、舱盖 32×64、长侧面 64×20、端面 32×20。低于 API 最小画布的侧面和端面置于黑色遮罩保护的 32px 高画布内；输出后只裁去这些技术留边，再最近邻整数放大 4×，不改变 UV。

遮罩以 4×4 最小值保护结构，脚本只准备输入、裁切、精确配准、保留编号与导出；新纹理与做旧由 PixelLab 完成，未用手绘／程序生成污斑替代。

- `source/requests.json`、`prompt_*.txt`、`guide_*.png`、`mask_*.png`：真实接口、种子与输入。
- `raw/*.png`、`result_*.json`：未修改的原始输出、任务 ID 与实际用量。
- `source/layers/`、`editable/*.aseprite`：原基底与新 PixelLab 层。
- `source/composite_validation.json`、`artifact_validation.json`：范围／结构保护、哈希与母版回读。
- `source/baseline_file_hashes.json`：21 份既有运行资源、模型／布局及上轮候选，防止本轮覆盖。

实景检查发现第一版端面有 4 个原生可编辑像素被生成成近黑色，放大后读成缺口。使用 PixelLab 对该小区域单独返修：输入中仅把已拒用黑像素恢复为项目原始干净导图，用原生邻域遮罩让 PixelLab 重新绘制。最终只在此精确遮罩内合成两个 PixelLab 输出，未用手工颜色替换。原输出、`raw/shell_end_fix.png`、`source/repair_request.json`、修前实景及遮罩均保留，未重做其余材质。

实际用量：4 次材料生成＋1 次端面局部返修，每次 10 generations，合计 **50 generations**。最终为 4 张材质图和 4 份 Aseprite 母版；21 份既有资源／上轮文件的本机哈希保持，母版回读与 PNG 逐像素一致。

## 审查边界

最终本机回归：22,958 项运行时不变性检查通过；27 张 1280×720 实际 GPU 截图，60 项机位／FOV／姿态／恢复检查通过。A 恢复图与最初 A 逐像素相等；三组继续使用相同原 shader／光照。最终导入、运行、截图的 `ERROR:`／`SCRIPT ERROR:` 均为 0，临时日志不上传，结构化结果保留。

实景中，r21 的舱体肩部／侧面与墙边从细散颗粒转为更大的阶梯块，强度高于 r20；端面的纯黑缺口已纠正。仍保留原几何轮廓与空间受光，因此这里只确认候选有可见差异，不宣称已完全复现参考或由用户批准。

这轮只测试贴图的颗粒和图形组织；高分辨率轮廓、原有空间光照及临时纸片主角保持。新颜色的间接反弹未重烘，不能当作最终光照交付。正常游戏视距与近景须分别查看，不能只凭贴图放大图宣布已达到参考。

本轮候选需用户审图，不把 4× 网格自动升级为项目标准，也不把局部效果当成全室批准。
