# Room 1 左墙黑块修复 r2

2026-10-27。已接入当前出仓r3及墙地局部材质小样。真实Godot同机位截图确认：左墙下沿异常黑块消失，墙面与舱体没有沿三角线明暗切割。材料候选仍待用户审查。

[查看修复前后](preview.html)。旧错误的通道隔离证据见[诊断记录](../room1_left_wall_dark_patch_diagnosis_v1/README.md)。

## 原因与修复

旧共享光照图里，左墙内侧UV2与P02／P11／P13／P20舱壳有重叠，把舱壳数据写到墙面。此前UV0修正没有处理光照UV2。

最终流程把129个接收网格的临时副本合并，在单一网格的编辑模式中使用Smart Project，以连续平面构成图岛并统一排布，再按角点ID把UV2传回原网格。不会把平面上的每个三角拆成独立岛；左／右墙内面两三角的共享UV对角边有单独检查。

临时副本也用于一次性烘焙，完成后删除；导出仍是原169个独立网格。64样本、2048图集、四条原连续发光面的位置／颜色／能量、0.06m烘焙宽度、4px扩边和既有HDR降噪保持。模型、20舱布局、P12的45°开盖、镜头、原生像素颜色贴图及Aseprite母版保持。

逐网格烘焙曾长时间运行；最终一次性CPU烘焙实际约7秒，已用正式入口完整重建。逐三角Lightmap Pack方案因画面出现对角接缝被弃用，没有作为最终结果。

## 检查与实际画面

- `uv2_layout_record.json`：17,908个有效几何三角都有有效UV2；零退化、零越界、零正面积重叠，UV0哈希保持；左右墙内面对角边连续。
- UV面积退化阈值为1e-12；重叠报告阈值为1e-8。有效但小于一像素的倒角三角不等于退化；不把排布参数误称为实测像素间距。
- `export_scope_readback.json`：169个网格节点，无新增或缺失节点；每个三角角点的位置、UV0和原法线保持，节点变换保持。导出会扩展UV接缝顶点，缓冲索引不是逐字节相同。
- Blender重导入会量化自定义法线；`room1_restore_glb_normals.py` 按原三角角点恢复原float32法线。最终读回最大法线差为0。
- `evidence/`：原材质、小样材质各一组旧／新烘焙1280×720截图；`capture_record.json`记录相同机位、朝向、FOV及实际数据路径。
- 当前材质小样原有8张截图已重新渲染。没有提亮截图、涂掉黑块、关闭人物阴影或更改灯光参数。

未新增玩法测试套件；本轮验证为资产读回与实际Godot渲染。未调用PixelLab。

## 工程与接入

- `room1_open_hero_uv2_r2_packed.blend`：可编辑工程，独立网格、UV0／UV2、打包颜色图和HDR光照、原连续发光面。
- `assets/art/room1_open_hero_uv2_r2/`：配套GLB、降噪EXR、网格映射、烘焙参数与UV检查记录。三项运行数据须配套使用。
- 当前 `room1_pod_exit_animation_r3.gd` 默认读取新目录，派生 `room1_surface_sample_r1.tscn` 随之修复。r1／r2旧版本和旧烘焙目录保留。
- `legacy_lightmap_for_review`只用于恢复旧错误基线。运行时根据所选GLB目录读取对应网格映射。
- 重建：Blender运行 `scripts/dev/bake_room1_open_hero_uv2_r2.py`；需NumPy（Blender自带）。`ROOM1_UV2_LAYOUT_ONLY=1`只检查布局；已存在运行结果时默认拒绝覆盖，明确重建可设置 `ROOM1_UV2_R2_ALLOW_OVERWRITE=1`。

原始未降噪EXR和试验日志留本地、不上传；打包Blender工程、运行时HDR与生成入口足以继续编辑和重建。
