# 单舱 v4 放回 Room 1：实际光照检查 v5

2026-10-27，待用户审图。此次不重新设计模型或贴图，仅把上一轮v4候选放回P12原位，比较开盖和闭合。

## 使用

Godot打开 `scenes/dev/room1_pod_room_v5.tscn`，F6运行。默认P12为新v4开盖，其余19舱及墙地沿用r9房间。V旧／新，O新舱闭合／45°打开，T新玻璃显隐，G舱内灯，L灯带，N固有色诊断，J回观察点，H说明，WASD移动。

[实际对照页](preview.html)包含原游戏镜头、同机位近景、低机位截面、头窗透明和内腔光控制图。所有图1280×720，没有截图提亮；固有色图只作纹理诊断，不当作实际照明效果。

## 接入方法

- P12世界坐标保持Godot `(3.525,0,-7.65)`，没有挪动舱位或房间。人物初始位置保持；补充游戏截图只临时旁移审图人物，以免遮挡P12，不改人物资产。
- 房间仍使用r9墙地与对应照明，原灯带、环境亮度、曝光、屏幕发光和舱内光强度不作额外提亮。原P02/P17状态保留。
- 新舱是不透明组件＋透明玻璃＋发光屏幕分开绑定。保留v4八张颜色图与真实UV0。屏幕沿用房间现有屏Shader；玻璃沿用v4显式alpha Shader，玻璃面本身没有自发光。
- 新舱使用当前房间的四条原发光带和场景遮挡，在Blender中为开／关两姿态分别烘焙**新舱接收的光照**，使用自己的UV2和EXR。没有把旧P12光照UV硬套给新截面，也没有拿单舱审图灯光冒充房间照明。
- 两姿态均1024样本、2048光照图；沿用现有流程对线性光照降噪，以32位ZIP EXR保存。降噪只处理光照，不平滑或重画像素颜色图。最终EXR已重新打包进相应房间Blender工程。
- 不透明表面复用原房间P12相应Shader及参数，只替换当前颜色图和对应新UV2光照；内腔保留房间现有受控灯算法。旧／新切换同时更新屏幕光晕遮挡模型，避免隐藏的旧盖继续遮挡或透出光晕。

## 边界

这是**P12局部材质／受光检查**。墙地和其他19舱的原r9光照贴图没有重新烘焙，因此新盖对周围地面产生的静态投影和细微二次反弹仍沿用原开盖房间；闭合图不能当成最终完整闭合场景的全室烘焙。定案后再统一整室几何与GI。

开关是两种静态姿态，不是新开盖动画。原碰撞／出仓交互没有重做，不能把移动审图当成新闭合碰撞验收。主场景、工程显示分辨率及原实验均保留。地面r9仍是用户暂时搁置的候选，不因此转为批准。

v4模型及八份分层Aseprite仍以 `docs/art/experiments/room1_pod_volume_v4/` 为源，本轮没有另画贴图、没有新AI调用。当前文件只增加房间检查所需UV2、光照及绑定。

## 文件与复现

- 新接入导出／两姿态光照：`assets/art/room1_pod_room_v5/`。
- Blender局部烘焙脚本和几何／UV／发光带记录：`source/`。
- 实际Godot截图与机位／开关状态：`evidence/capture_record.json`。
- `capture.gd` 可用Godot命令行 `--rendering-method gl_compatibility --resolution 1280x720 --script res://docs/art/experiments/room1_pod_room_v5/capture.gd` 重拍。
- 重建顺序：Blender后台执行 `source/bake_pod_room.py` → `source/denoise_pod_room.py` → `source/check_packed_source.py`；Godot重新导入后运行捕获脚本，再用Python执行 `source/check_assets.py`、`source/check_capture.py`。烘焙脚本覆盖本版本输出，需保留已审版本后再主动重建，不用于批量改动其他实验。

最终美术判断以正常房间照明截图为准：打开后的实体感、暗处旧化是否足够可读、闭合头窗是否透出内腔、关灯后是否仍像玻璃；技术检查不等同于用户认可。

## 本轮观察

正常房间光下，开盖的窗框、内衬与舱口仍能读出实体截面；闭合外壳的装配边、涂层缺损与积旧在近景可辨，原游戏距离下更弱。玻璃显隐和反光开关均有独立变化，透明头窗确实透出床面。关闭舱内灯后仍能见到暗色内部轮廓。

沿用的现有舱内灯会把头部床面照得较亮，近景出现偏白亮区，压低该区域材质细节；本轮保留现有强度，供判断是否下一步调整，不把高亮当成不透明玻璃。原游戏站位的胶囊人物会挡住P12，因此额外保留一对原FOV、旁移站位的游戏图。

玻璃和固有色N模式往返逐像素恢复。旧房间基准与V回退仍存在极少数像素微差，数值完整记录在 `source/capture_quality.json`，没有把它宣称为整幅图完全一致。实际捕获过程无Godot脚本错误。
