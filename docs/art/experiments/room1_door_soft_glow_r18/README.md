# Room 1 门灯柔光 r18

2026-10-29。用户认可r17的门沿灯方向，但认为过于线条化，希望像室内灯带一样有透出的薄柔光。本轮只增加可见灯芯的局部光晕，保留r17颜色、窄灯芯、内嵌位置、门板遮挡与普通暗色外框。**待用户审图**。

[同机位对照](preview.html)。Godot打开 `scenes/dev/room1_door_soft_glow_r18.tscn` 按F6，F4切换r17硬灯芯／r18柔光；不是恢复早期整框变绿。F5入口未替换。

## 实现与范围

- 保持r17实际灯面及材质不变。另建独立可见灯芯遮罩：四个灯面进入发光源，门板、房间和舱体进入黑色深度遮挡，纸片主角按实际透明轮廓遮挡；同步当前门板位置及idle／walk精灵帧。
- 只对深度遮挡后仍可见的灯芯做两层高斯扩散，近层sigma1.7、远层3.5个当前内部渲染像素；减去部分原芯贡献，避免把灯芯过曝成粗白线。独立叠加在像素场景内部，沿用既有最近邻显示，不模糊墙地和像素颜色图。
- 关闭／扫描／拒绝时没有发光源；半开时，被门板挡住的右侧不产生光源或光晕。可见灯芯附近允许有几像素的柔光越过轮廓，这是光学光晕的表现，不能误称为严格逐像素的物理遮挡。
- 这是屏幕空间柔光，**没有增加真实体积雾、烟尘、动态GI或绿光点光源**；不重烘墙地，不改变灯芯基础颜色、PixelLab贴图、UV、布局、门运动／碰撞或认证小窗。PixelLab调用0次，此轮没有像素美术生成／返修。
- 为防止影响休眠舱屏幕和原墙灯，新增独立遮罩、相机及四个模糊视口；没有往旧屏幕光晕里添加发光源。源相机跟随实际渲染相机与分辨率。该审查实现有额外绘制／后处理成本，尚未做最终平台性能优化。

## 检查结果

- [真实通行测试](source/runtime_validation.json)：扫描、开门、人物穿门、关门、无权限提示和碰撞同步通过；柔光独立世界、相机同步、门板遮挡代理和F4关闭通过。检查命令同时拒绝Godot错误日志，不能只凭报告中的PASS。
- [图像检查](source/render_validation.json)：闭合时源遮罩和光晕都为零；20%／50%开门时，被挡住的右侧没有光源和远端光晕。六处前后排／左中右游戏机位，门灯周围之外的图像变化均为零；灯在画面外的四个机位整体无变化。
- [截图记录](evidence/capture_record.json)：输出1280×720；开／关柔光保持相同机位、曝光、颜色和门状态。另查看正面、左右斜视、人物遮挡及对应实际发光源遮罩。主角遮挡测试只临时移动截图中的角色，不写回游戏位置。
- 光晕专题通过不代表整套房间美术定稿；这里没有改动／重验旧烘焙的UV图集或复制新舱到其他19舱。参考r17已记录的实物门沿LED，Pixel Canals技术方向和PixelLab像素工作流继续保持。
