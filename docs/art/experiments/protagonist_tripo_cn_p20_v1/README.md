## 实际生成方式

通过 Chrome 扩展操作 Tripo 国内版官方 Studio，不调用开发者 API。未找到可直接使用的已连接 Tripo 插件，因此沿用当前已购买的网页订阅权益，不把网页积分与 API 账户混用。

选择 Smart Mesh P2.0，多角度输入中只放两张独立图片：项目自有[正面 v2](source/input_front.png)与[修正背面 v2](source/input_back.png)。侧面留作本地工作参考，没有把同页排版的三个人物上传为一个模型，也没有上传 Pixel Canals、INSIDE 或第三方人物素材。

设置：一个生成结果、Private、Quad、目标3000面，未请求贴图。未执行分件、UV、绑定或局部重试。界面生成后读数为 **3020面、3218顶点、Quad**；这是网页统计，实际导出网格统计另见审计，不把 GLB 三角面数与 Quad 数混为一谈。

本轮使用一次随账户提供的 P2.0 赠送试用机会，Trial x2 → x1，显示费用100划除后为0。账户积分前后均3300，实际观察消耗0点。模型是在用户有效专业版订阅期间新生成，并保持网站私有。上传、生成、后续游戏使用的权利依当时[用户协议](https://www.tripo3d.com/terms)及第三方权利约束；本记录不把 AI 生成或技术检查当成绝对不侵权保证。

## 下载与检查边界

只使用官方 Export，下载一份 GLB 及一份 OBJ 压缩包。GLB 下载事件没有通过自动化接口返回路径，但文件实际保存到正常 Downloads 文件夹；检查文件后直接使用，未重复点击 GLB 导出、未提取网站隐藏网格。OBJ保留用于核对四边面，GLB保留通用导入版本。

Blender 中保留原始模型，不擅自修头发、减面、改轮廓或重做服装。灰色 Workbench 仅用于审查体积，不是最终像素贴图。相机和检查设置不属于正式游戏相机。

后续必须先审正、侧、背、斜视和后发局部，确认外形后再考虑合理分件、变形网格、UV及像素贴图。没有绑定、动作、Godot角色替换或实机角色验证；Room1、4F、v6门墙与场景光照保持现状。正式材质继续 PixelLab 主体制作、Aseprite 局部精修流程。

用户最终美术认可：**尚未获得**。实际网格与视觉检查结论将在下方交付检查中记录，不以网页上的 Quad 标签代替审图。

## Blender 实际检查结果

| 导出 | 顶点 | 面 | 三角化后 | UV／骨架 |
|---|---:|---|---:|---|
| OBJ（检查工程主源） | 4110 | 2486四边面＋534三角面＝3020面 | 5506三角面 | 无／无 |
| GLB（另行导入审计） | 3218 | 5506三角面 | 5506三角面 | 无／无 |

两份原始文件在导入、检查、保存前后 SHA-256 保持。GLB通常通过三角面存储，因此保留官方OBJ供后续四边面整理。OBJ导出有顶点拆分，连通组件计数与GLB不同，不把193／38个组件称为人体、衣物或头发的合理拆分。GLB仍有880条边界边和2条超过两面的非流形边；当前不是可直接绑定的变形网格。

实际姿态为Blender +Z朝上、面向+X；已按真实解剖朝向设置正面+X、背面-X、侧面-Y和后发近景，没有为了标准轴旋转或改动原始模型。源模型包含一块实际地面平面，不能将包含地面的1×1m包络当成角色身体宽度或最终物理身高；正式角色交付前应单独处理底板，当前原始源保留它。

目视与独立复核见[视觉记录](source/visual_review.json)：主角是一个连续人物，白袍、袖子、四肢有体积；后发主体比H2.5更完整，但两侧仍有游离／环状细发片、发尾偏硬。手脚仍粗，侧面脚形偏尖。面部简化方向符合当前要求，但没有游戏镜头下的可读性结论。

因此本轮交付为**可审看的起始灰模**，不宣称最终造型或可动画成品。下一轮先由用户确认外形，再针对头发轮廓、底板和手脚做有限整理，然后才进入分件、UV及像素贴图。
