# Room 1 移动同步 r2 — 2026-10-14，待审

用户报告低分辨率画面观感怪、走动持续抖动，且误关了预览。本轮重新打开独立修正版，默认回到F1原画；F2／F3保留像素密度对照，F4开关移动插值。之前静态对照不代表移动观感通过。

原因检查：旧版CharacterBody、FollowTarget和相机在物理帧更新，渲染相机直接读取当前离散变换，没有跨物理帧插值。低分辨率最近邻放大同时放大了透视细线的像素相位变化，两者可叠加。

新脚本分别记录物理上一步／当前人物位置，在渲染帧使用Engine.get_physics_interpolation_fraction插值；人物显示网格、FollowTarget、固定高度／朝向相机、屏幕光晕镜头以及动态阴影接收位置在同一显示帧同步。实际CharacterBody与碰撞仍使用物理位置，不预测穿透，不更改物理频率。R复位与1～9定位会重置历史，避免跨房间拖影。此方案有约一物理步的显示延迟。

场景：scenes/dev/room1_pixel_motion_test_r2.tscn。WASD走动、F1原画／F2中／F3粗／F4插值，R复位，K人物阴影、C碰撞、H说明。没有通过模糊、提高灯光或改变机位掩盖抖动。

验证刻意设物理10Hz／渲染上限120FPS，采样90个渲染帧：旧读取最大镜头步长0.20m、75个停顿帧；插值后最大步长约0.0333m、0个停顿帧、0个反向帧。测试后恢复原频率。前排P02碰撞、镜头高度／朝向锁定和重定位历史清零通过，保存两张静态预览及validation.json。

这不是声称低分辨率透视完全无闪动：细线、远处小字仍会因像素采样变化闪烁，摄像机同时前后移动也有透视缩放。F1用于判断物理顿挫与像素闪动的区别；用户最终移动观感仍待试玩。全项目规格、原模型／贴图和旧对照保留。

依据：[Godot物理插值](https://docs.godotengine.org/en/4.6/tutorials/physics/interpolation/physics_interpolation_introduction.html)。
