# Room 1 光照制作与交付检查

2026-10-27。用户要求按整场景检查并避免同类问题反复交付。本规则适用于后续Room 1烘焙／UV／场景材料工作，也作为其他场景的检查方法；不替代现行美术简报。

## 必须同时通过的检查

1. **图集与连续面**：接收网格共享图集，全局核对有效几何三角是否都有有效UV2、是否越界、是否正面积重叠；阈值、单位和小于一像素的有效三角需分开说明。墙面等连续平面不能任意拆成独立三角岛；核对共享边，而不只查重叠。
2. **扩边与留白**：烘焙dilation、图岛留白和过滤一起检查。排布工具的margin参数不是实测最终像素间距。未测得足够间距时必须检查紧邻图岛边缘的实际采样，不能写成“已证明无串色”。
3. **整套数据匹配**：GLB的UV2、光照图和网格映射必须来自同一版本。导入保留UV2精度，HDR按线性数据读取，原生像素颜色图使用最近邻；避免对颜色贴图做降噪。几何／灯光变化后禁止直接套用旧烘焙。
4. **连续灯槽与自发光**：共面分块墙应使用连续且等密度的光照坐标，不能让门楣与相邻墙各自形成亮度台阶。发光面使用统一的发光数据，避免被分块烘焙光或人物阴影重复调制。UV0预期覆盖0–1的隐藏面也要检查越界夹取，不能只看可见墙。
5. **采样与降噪**：同时看原始光照和降噪结果。零UV重叠不代表照明质量合格；原始噪声过大时，应提高采样并检查收敛，不能依赖强降噪、模糊、提亮或局部涂抹。1024是当前r4的已检查候选值，不是所有场景都能合格的固定标准。
6. **实际整场景审图**：既有游戏镜头覆盖前后两排的左／中／右；另检查四角、墙脚、门洞、灯槽、连续地面和全部20舱。技术巡检相机可以临时改变，但不能保存进游戏镜头。剖切隐藏／仅投影的墙必须临时真正显示；总览里被挡住或落在画框外的对象不算覆盖。
7. **修前／修后回归**：保留相同机位、比例、分辨率和曝光的对照；同时检查旧黑块、新墙角波纹、三角明暗切割、图岛边缘串色和灯槽异常。截图需实际打开观察，不能用哈希、静态读取或“渲染成功”替代画面通过。
8. **交付边界**：出现新的同类伪影则继续修复，不以局部问题消失为完成条件。保留版本化源工程、运行数据、检查记录和截图，再切换默认入口。明确区分光照专题检查通过、其他已知美术缺陷和用户审查通过。

当前表面候选入口为`scenes/dev/room1_surface_lighting_r7.tscn`，在r6墙／r5地坪和固定漏液上使用新烘焙。脚本`bake_room1_surface_lighting_r7.py`从r4源保留几何／UV2／四发光面，只改变七个墙地材质的颜色输入，按现行Godot世界投影采样。DIRECT＋INDIRECT、COLOR关闭，避免接收面固有色重复相乘。
