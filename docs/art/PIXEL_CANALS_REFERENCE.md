## 3. 模型结构：轮廓优先，面数按可见贡献分配

### 3.1 大体块与关键轮廓

**观察 O：**Matcap 中，远处建筑的丰富窗格退化为简洁体块；桥梁、栏杆、屋檐、台阶仍保留空间形状。Wireframe 又表明屋顶并非一张任意平面，局部有更多分段。

**推测 H：**作者把几何投入到轮廓变化、遮挡、转角和视差上，把大部分表面信息交给贴图。这是一种有选择的低模设计，不等于每个物件都采用最少面数。

**建议 R：**判断是否建模时，先问三个问题：

1. 它是否改变游戏 Camera 下的轮廓或遮挡？
2. 它是否需要真实空间／碰撞／开合运动？
3. 它在目标画面里是否有足够像素，能让这段几何被看见？

三项都不成立时，优先放进贴图或取消细节。不要按参考模型的 29.8k 总三角数给单室设硬性预算。

### 3.2 几何与贴图分工

| 内容 | 在参考中看到的现象 | Room 1 建议 R |
|---|---|---|
| 大轮廓／空间结构 | 桥、建筑体块、台阶在 Matcap 中仍存在 | 舱体底座、内收主体、独立舱盖、门洞与墙体用几何 |
| 表面分区 | 窗格、木板色带、招牌在颜色通道里仍清楚 | 编号、接缝暗线、状态图案、少量老化用像素贴图 |
| 突出的构件 | 屋檐、栏杆等有实体层次 | 只有影响轮廓／操作的盖边、底座内收等保留体积 |
| 图案中的亮暗 | Base Color 存在亮边、暗带与材质色差 | 结构色阶可画入贴图；剧情变化的投影与光照单独处理 |
| 植物等复杂轮廓 | 可见像素化轮廓；部分构件从侧面呈薄片状 | 不据此认定全部使用 billboard；Room 1 不引入植物或相应资产 |

### 3.3 模块化能确认到什么程度

**观察 O：**窗带、栏杆段、建筑立面单元存在重复节奏；2D 检查图像有多个可辨认的局部图案。

**推测 H：**这些现象适合通过模块复用、共享 UV 区域或图集完成；本次不能证明作者使用链接复制、实例、trim sheet，或一个特定模块网格。

**建议 R：**Room 1 更适合一个自有休眠舱母版、重复实例和少量状态差异。独立的舱盖与认证面板保留功能边界；编号可用预留图集区域或另一小图案层。编号／文字不能跟随镜像 UV 一起反转。复用结构有助于表达标准化，不需要用随机破损把 20 个舱做成 20 个独立设计。

## 4. 贴图与材质：像素是画法，不只是分辨率

### 4.1 像素颗粒与颜色组织

**观察 O：**表面有清楚的色块、阶梯状边缘和簇状污迹；木结构以较大棕色带区分层次，墙面以浅底色和少量灰色块表达接缝／老化。不同区域的色相与明度分工明确，未见每个表面都依赖同样强的细碎噪声。

**推测 H：**低有效分辨率、清晰采样和有意识的像素簇共同形成观感。不能确认原图一定很小：高分辨率文件也可能保存经过整数放大的像素绘画。也不能从这些画面认定全作采用固定数量的全局调色板。

**建议 R：**先设计可读的像素簇：大底色、结构暗面、少量亮边、局部材质痕迹。墙体与舱壳可以都偏浅，但用色温／明度层次区分；避免到处铺均匀噪声，吞掉门洞、人物和舱盖的形状。

### 4.2 贴图中的明暗与实时光照

**观察 O：**Base Color 保留了很多视觉信息；最终渲染与它又有可见差别。因此「颜色图承担部分造型」成立，「全部明暗都是烘焙」「完全没有光照」不成立为已证事实。

**建议 R：**把不随剧情改变的材质色差、细小接缝和结构层次放入像素颜色图；把应急光、主角舱的光、人物移动带来的阴影作为独立变量。避免在颜色图里画死很强的朝向性投影，再用实时灯重复照一次，产生互相矛盾的阴影。

参考标记为非 PBR，值得借鉴的是颜色主导的材料表达。Room 1 仍需区分哑光外壳、工程复合墙体和磨砂观察区；不能把非 PBR 简化为「所有物体一个无光照材质」。

### 4.3 三种“像素尺度”必须分开

| 尺度 | 决定什么 | 为什么不能只设一个参数 |
|---|---|---|
| 贴图 texel | 表面图案的绘画颗粒 | 同一图集分给不同大小的面，世界尺度可能不同 |
| 世界中的 texel 密度 | 每米表面分配多少 texel | UV 拉伸、重复与不同轴向都能改变密度 |
| 最终屏幕像素 | 轮廓、投影和最终画面的采样网格 | 由投影、Camera、渲染分辨率和显示缩放共同决定 |

**推测 H：**参考的近 2D 感首先来自表面绘画；本次没有验证全画面是否经过统一低分辨率后处理，也没有证明每个 texel 都对应一个屏幕像素。

**建议 R：**以休眠舱和人物在最终 Camera 下的可见高度选择贴图密度。正交镜头下可先用 `画面像素宽 / 对应世界宽` 估计比例；斜向面和地面仍受投影压缩，不会自动得到统一正方形网格。所有贴图尺寸、逻辑画布、角色像素高度继续 **TBD**。

## 5. 为什么 3D 空间会接近 2D 像素作品

下面是基于观察的解释（推测 H），不是作者公开的制作配方：

1. **贴图已经完成大量视觉造型。**窗、材料痕迹、明暗色带具备像素画的组织方式，几何不必逐个复刻。
2. **几何保留真正需要的空间。**轮廓、遮挡和层次随视角变化，提供 3D 的深度；大面保持简洁，减少连续曲面带来的光滑 CG 印象。
3. **默认构图把空间压成清晰的画面层。**前景桥／栏杆，中景立面，远景建筑，各层有可辨认的视觉作用。
4. **颜色信息压过写实材质反应。**非 PBR 标记与 Base Color 的丰富信息支持这一判断，但仍有最终渲染的光感补充。
5. **展示视角限制了需要同时阅读的信息。**旋转到边缘或高处时，大体块、薄片和重复关系更明显，效果并非任意角度都等价。

这条路线需要同时设计模型轮廓、像素贴图、照明和 Camera。仅把现成高细节灰模缩小分辨率，仍可能得到密集锯齿、糊掉的细节和写实光照，而不是经过组织的像素画。

## 6. 镜头与构图

### 6.1 参考作品的观察边界

**观察 O：**默认画面强调立面与有限地面；近处桥／栏杆较大，远处建筑较小。Viewer 允许自由 Orbit，旋转会明显改变遮挡和构图。

**推测 H：**默认画面具有透视式的近远尺度感；没有读取精确投影类型、焦距、俯角，也不能由 Viewer 的自由 Orbit 推断作者计划的游戏操作方式。

### 6.2 固定／受控镜头对本项目的价值与限制

| 价值 R | 相应限制／验证问题 |
|---|---|
| 可以围绕一个主视角选择有效轮廓与 UV 密度 | 自由转镜头会暴露薄片、背面简化和不一致的像素密度 |
| 重复舱体可以形成规则的前／后层次 | 近侧舱可能挡住人和侧面操作位，尤其在近侧视 Camera 下 |
| 固定距离让编号、门、人物有稳定画面大小 | 缩放或切镜头后，小编号可能消失，贴图颗粒也会变化 |
| 低俯角保留立面与压迫感 | 通道在图像上会变窄；实尺不拥挤不等于画面可读 |
| 正交投影可以减少近远尺度变化 | 地面纵深仍被压缩，也不自动解决斜边与运动闪烁 |
| 轻微透视能保留自然空间感 | 前后排颗粒与人物大小更难完全统一，需要专门比较 |

Room 1 沿用现有低角度、近侧视方向；不为了展示全部 20 舱把 Camera 抬成 RPG 俯视地图。v0.43 已暂停几度差异的反复微调，本次没有重开 A/B/C 或改写 Camera 参数。后续若测试技术路线，应先继承已接受的构图，再比较表现方案。

### 7.2 各对象的制作分工提案（建议 R）

| 对象 | 几何承担 | 像素颜色／材质承担 |
|---|---|---|
| 墙／地面 | 墙角、真实门洞、地面连续性及遮挡 | 材料色差、克制的模块接缝、少量积灰／局部老化 |
| 标准舱 | 已有底座、内收主体、独立低舱盖、头端观察区；影响轮廓的倒角 | 编号、结构色阶、接缝、状态差异；少量大像素簇 |
| 舱盖／观察区 | 开合部件边界与可见头端范围 | 磨砂观感和模糊人体提示；不追求复杂写实折射 |
| 唯一人员门 | 净开口、门扇轮廓及以后开启空间 | 权限／状态标记、面板分区；不放大成货运门 |
| 壁面认证面板 | 原位极简功能占位 | 可辨认的小屏／状态图案；造型仍未批准 |
| 人物 | 延用比例与站位参照 | 以后单独决定 3D 人物或 Sprite3D 等表现；本研究不替换人物 |

为避免把 20 舱变成视觉噪声，可复用同一几何和基础贴图，仅让主角舱的开闭／残余光状态有必要的区别。编号可存在于表面；实际需阅读的身份信息可通过交互 UI 呈现，不要求远处每块小字都能在常规镜头里读清。

### 7.3 保留项目自身的材料与情绪

- 沿用洁净、正式、可靠、制度化的生命保存设施身份；不要复制沿河商业街的木结构、店招、绿化或高彩度生活氛围。
- 材料以现行美术文档的哑光耐腐蚀外壳、矿物／工程复合结构和工程陶瓷为背景。用像素色阶表达差异，具体色板仍 TBD。
- 老化优先表现接缝积灰、表层褪色、密封件龟裂和局部损伤；不把所有白色设备涂满黑灰噪点。

- 主角舱与出口的可读性优先于展示所有舱的表面细节；保留空通道和人员缺席的情绪作用。

## 8. 可复现流程提案：Blender → 像素贴图工具 → Godot

以下都是 **建议 R，尚未执行**。本轮没有新建资产或原型。

### 8.1 Blender：保留尺度，设计可见轮廓

1. 从现有工程基准建立独立的技术研究副本，保留实尺、坐标、舱位与镜头。工程模型提供空间，不自动作为最终工业造型。
2. 在目标 Camera 下评估一件标准舱的底座／主体／舱盖轮廓；曲面与倒角按画面贡献简化。母版未批准前不批量做最终变体。
3. 按功能保留可动件；UV 为大平面提供规则区域，弯角／斜面检查拉伸。共享区域保留必要边缘留白，避免缩小时相邻图案串色。
4. 以同一组参照面的 texel 密度检查舱壳、门与墙；不要只检查整张贴图文件是否同尺寸。
5. Blender 的 Image Texture 使用 **Closest** 作为清晰像素采样的起点。这是官方提供的最近邻选项，不是对 Seafoam 设置的断言。[Blender Image Texture 文档](https://docs.blender.org/manual/en/5.1/render/shader_nodes/textures/image.html)
6. 导出可交换的 `.glb`，保留源 `.blend` 与独立贴图；到 Godot 重新检查采样、透明、照明与 Camera，不假定 Blender 的任意节点组合都会原样迁移。Godot 官方推荐 glTF 2.0 作为 3D 交换格式。[Godot Available 3D formats](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

### 8.2 Aseprite／Pixelorama 等像素工具：围绕 UV 画信息

1. 导出 UV 参考层，分别保留材质底色、结构暗面、亮边、编号／状态和老化图层。
2. 用硬边像素笔与少量色阶组织像素簇；避免自动柔化边缘。扩图时保持整数最近邻缩放，颜色图优先无损 PNG。
3. 先看整舱和实际画面，再看放大的单个 texel。图案不需要在贴图编辑器里非常密集才算完成。
4. 把主角舱、停止舱和编号差异设计成受控状态；镜像部件需要核对文字方向、观察区朝向与像素光向。
5. 回 Blender／Godot 检查 UV 接缝、斜面颗粒和地面远处缩小表现。具体工具不限定，源文件应保留可编辑层。

### 8.3 Godot：分开控制材质采样与最终画面网格

现有项目仍为 2D，配置声明 Compatibility。未来若做技术试验，应隔离于正式工程；不得把研究文档中的参数直接写进当前 `project.godot`。

**材质起点：**使用 `StandardMaterial3D` 的 `texture_filter` 对比 `NEAREST` 与 `NEAREST_WITH_MIPMAPS`。最近邻保留近景颗粒，但远处／斜面可能颗粒闪烁；mipmap 改善缩小采样，也可能削弱像素簇。应在固定镜头和运动时分别评估，不能规定全项目一律关闭 mipmap。

**照明对照：**Unshaded 可作为颜色图基线，但它禁用光照交互与接收阴影，不能直接承载 Room 1 的动态明暗叙事。再比较低高光的受光材质，必要时才研究有限明暗级数的自定义 Shader；本次没有写 Shader。[Godot BaseMaterial3D](https://docs.godotengine.org/en/stable/classes/class_basematerial3d.html)

**最终网格：**先比较「高分辨率 3D + 清晰像素贴图」和「固定低分辨率 3D SubViewport + 最近邻整数显示放大」。后一种候选结构为：

```text
独立研究场景
├─ SubViewport（分辨率 TBD）
│  └─ 3D 空间 + Camera3D
└─ 2D 显示层
   ├─ 最近邻显示该 ViewportTexture，保持整数倍缩放
   └─ UI（按所需清晰度单独渲染）
```

Godot 的 SubViewport 可以独立渲染并提供 ViewportTexture；整数缩放可避免显示时像素宽度不均。以上为候选组织方式，不是已实现效果。[Using Viewports](https://docs.godotengine.org/en/stable/tutorials/rendering/viewports.html)、[Multiple resolutions](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)

不能只降低 `scaling_3d_scale` 就假定得到最近邻像素放大：官方 3D resolution scaling 包含 Bilinear 等重建方案，结果与硬边整数放大不同；FSR 还受渲染器支持限制。当前 Compatibility 无需为本研究切换渲染器。[Resolution scaling](https://docs.godotengine.org/en/stable/tutorials/3d/resolution_scaling.html)

抗锯齿、Bloom、景深、色调映射也应作为独立对照变量。先建立清晰基线，再判断哪些效果可保留；关闭所有效果同样不是已确认的生产规范。角色若以后采用 Sprite3D，还需验证朝向、深度遮挡、阴影与地面接触，不能把已有 2D 排序规则直接当成 3D 方案。

| 磨砂观察区怎样表达？ | 以后独立比较绘画式不透明／裁切与简化半透明方案 | 头端模糊人体提示是否成立；多个舱重叠时是否排序异常 |

未来最小技术试验可先使用一个自有标准舱、地面、墙面与原有比例参照，验证像素／材质链路；通过后再在保持布局的副本中看 20 舱整体。它应是另一次明确的制作任务。本轮没有创建这些资产，也没有更改现有工程。

## 10. 阶段结论

1. **最值得复用的是分工：**几何负责轮廓、空间、遮挡和运动；像素颜色图负责大部分表面信息与部分造型明暗。
2. **贴图画法决定效果下限：**清晰色块、像素簇、信息层次比单纯减小贴图／屏幕分辨率更重要。
3. **固定或受控 Camera 与此路线相容：**能稳定构图与颗粒，代价是必须检查近侧遮挡、缩小采样和运动闪烁；不能照搬参考的任意 Orbit。
4. **Room 1 应保留当前十字工程骨架与生命保存设施身份：**复用标准舱和功能分层，保持克制、洁净、制度化，不移植商业街视觉，也不加物件填空。
5. **路线值得做自有小原型，但尚未证明可以直接替换现有 2D 工程：**精确分辨率、UV 密度、Shader、照明、透明与人物表现都需验证。参考作品的原始贴图尺寸、完整 UV、过滤设置、节点树与运行流程仍未确认。

### 11.3 对本项目候选的直接核对

以下来自本仓库文件和已有实际截图，不是对参考作者的推测：

- [当前候选画面](experiments/room1_surface_full_room_r1/evidence/01_both.png)中，墙体大面仍近似平色，地面材料起伏很弱；灯面很亮，休眠舱与地面处于明显更暗的范围。画面没有达到用户要求的参考精细度。
- 复用的 `wall_sample.png`（128×136）与 `floor_sample.png`（128×128）主要包含大块材料色差；墙图虽有上下结构带，候选 Shader 又刻意保留原 r4 灯槽、保护带，没有重新绘制这些结构。
- `scripts/dev/room1_surface_full_room_r1.gd` 默认墙面强度为 0.5；Shader 实际混合为 `0.5 × (0.08 + 0.42 × feature)`。普通主面 `feature=0` 时只加入 **4%** 新图，交界最大 **25%**。因此“控制值 0.5”并不代表墙上能看见半强度的新像素绘画。
- 地面强度 0.6，以 3.2m 镜像重复材料图；这会扩展色块覆盖范围，但不会自动产生参考中的结构信息。把强度拉满或把图片放大，不足以补齐缺失的设计。
- 当前 Shader 已使用 `filter_nearest` 采样颜色图。问题不能归咎于没有开启最近邻；光照图仍为平滑采样，画面也保留连续明暗。

**判断／建议 R：**上一轮把“克制、少接缝、不随机脏污”执行成了几乎不画表面信息。原报告第 4 节本已强调像素画法；实际资产执行没有落实。偏暗的成图也让弱差异更难阅读，但本轮尚未进行中性照明对照，不能把照明宣布为唯一原因，更不能用整体增亮掩盖贴图不足。

### 11.4 下一次返工应改变什么（建议 R，尚未制作）

1. **重做可编辑的结构像素层，而不是继续稀释小样斑块。** 墙体主面保留连续暖灰；集中完成现有灯槽唇边、内槽暗面、灯罩边界、门洞收边、保护带上缘／暗面和墙脚接触。这些边缘在正常游戏尺寸必须读得出厚薄与材质差异。复合面、金属、磨砂灯罩各有不同的色阶组织，不共用同一种斑驳。
2. **材料时间感排在结构之后。** 墙面仅在已知交界安排低强度沉积与保护带旧接触，主面轻微大块色差；不照搬参考护岸的水渍、墙体分格、木梁或城市符号。地板仍为 A 版连续蓝灰，无十字路线、砖缝、明显刮痕或随机污渍；用大小有主次、轮廓经过整理的低对比材料簇，避免云状斑块成为唯一内容。
3. **先验证一个局部，再铺全室。** 保留当前布局与模型，取现有墙／灯槽／保护带／地面及一个舱作为自有验证片段，原版与返工版同机位比较。只重画当前范围，不新增家具、设备或未经确认的编号文字。若确有轮廓或厚度不足，另列几何问题，不能暗中自由扩建设计。
4. **至少保留两种显示检查。** 颜色图基线用于确认不依靠灯光也能读出结构；现有应急照明用于确认实际游戏中仍能辨认。中性显示只作诊断，不等于改定正式照明，也不等于所有材质改为 Unshaded。若颜色图明确而游戏中消失，再独立检查照明／色调，而非同时乱改所有参数。
5. **验收看实际画面。** 正常 1280×720 候选机位下能看出灯槽层次、保护带材质及地面克制的像素组织；无需放大截图或切差值图才知道做过。近景检查像素簇，远景和移动检查颗粒闪烁／重复；最终整室仍需遵守既有 UV、灯带连续性和全室巡检要求。1280×720 只是当前测试输出，不自动成为全项目规格。

本节确定的是执行差距与后续验证顺序；没有生成新贴图、消耗生成额度或声称返工已完成。休眠舱 v2 的既有基调认可继续保留；这次墙地候选不因此自动通过。
