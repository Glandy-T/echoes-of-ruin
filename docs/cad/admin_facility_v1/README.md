本版使用本机 FreeCAD 1.1.4 原生 Sketcher、App::Link、TechDraw 生成。范围仅为管理设施 1F/2F。它是一套**已知尺寸的工程基准、局部部件和带 TBD 的平面关系图**；门位、墙体和上下层注册还未形成完整建筑定位图。

### 坐标与未定位对象

- 统一轴向：+X 左→右；+Y 建筑正面→后侧。
- O1 是1F左前外包角 `(0,0)`。2F使用同轴向局部 O2；全局关系为 `X=X2+Tx`、`Y=Y2+Ty`，`Tx/Ty=TBD`。
- 部件母版、两个阵列范围验证分别使用独立局部坐标。默认原点/链接矩阵**不代表它们已放在建筑的 `(0,0)`**。
- A101/A102 内部虚线符号只保留草图和文档的相对关系，标注 NTS（不按比例）。可量取外包和独立尺寸详图，不能量取这些符号的门位/构件位置。
- 未生成3D上下层对位。未以1F层高5.5-6m的某个任选值作为准确楼面标高，也未任选2F居中偏移。

### 2F 工位顺序和范围验证

园区从管理设施向深处：`A/B → C/D/E → F/G/H → I/J`。
2F在统一建筑坐标中，**后侧升降台 → 正面**依次：`A/B → C/D/E → F/G/H → I/J`，左右不变。这实现了相对于园区总平面的前后翻转。

通道值未从范围中选定：同排1.2-1.5m、前后2.0-2.4m、外圈1.5-2.0m。只计算两个范围边界组合：

- 全取下限：`3×2.5+2×1.2+2×1.5=12.9m`；`4×2.2+3×2.0+2×1.5=17.8m`。
- 全取上限：`3×2.5+2×1.5+2×2.0=14.5m`；`4×2.2+3×2.4+2×2.0=20.0m`。

两种包络小于40×30m外包，只证明模块阵列的边界尺寸可容纳。墙厚、配套及最终落位未定，不能据此宣称净空、疏散或整层建筑协调已成立。模块内部桌面/椅子/屏幕位置未自行设定。

## 修改和保管

在 FreeCAD 中编辑 `Parameters` 的长度属性：12个原生尺寸草图和阵列链接表达式可以重新计算；`CAD_Live / A105` 投影尺寸随模型更新。图纸、部件、TBD和两种范围检查在树中分别分组。

**A101-A104、PDF/SVG和ParameterSchedule是本版参数快照。** 改参数后不可把旧导出当作新图纸。构建脚本当前包含本版已确认基准；直接重跑会重新创建v1并覆盖本目录v1草稿。因此后续应先复制为v2，依据当前编辑后的参数更新构建与导出，再重新核验。不要在未同步参数的情况下直接重跑覆盖用户编辑。

工程源代码：`build_freecad.py`（FreeCAD生成）、`render_pdf.py`（同一纸面图元输出PDF）。FCStd内嵌SVG纸面图元及模板，部件没有依赖外部Python代理。草图原图、文档快照和必要导出一起保留。

本版资料单独保存在 `docs/cad/admin_facility_v1/`。GitHub 交接包包含工程、图纸、来源副本、构建脚本、验证记录和待确认清单；本机配置、缓存、备份及一次性诊断脚本不纳入版本控制。

## 在另一台电脑使用

下载本目录后，在已安装的 FreeCAD 中直接打开 `admin_facility_v1.FCStd`。本版使用 FreeCAD 1.1.4 保存；打开和编辑工程不需要运行 Python 脚本。

`build_freecad.py` 需由 FreeCAD 自带的 Python 运行。`render_pdf.py` 需 ReportLab、pypdf 及 Windows 宋体 `simsun.ttc`；这些是重建 PDF 的依赖，不是读取现有工程和图纸的依赖。重建前遵守上面的 v2 复制与参数同步要求。

`manifest.json` 记录交接文件的大小和 SHA-256，便于核对下载内容。当前文件仍是 v1 验证稿，TBD 项不因上传而成为已确认设计。
